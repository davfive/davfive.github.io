CCA-F · Domain 3 · Task Statement 3.5

Iterative Refinement for Progressive Improvement

When prose descriptions produce inconsistent results, the fix usually isn't more prose.

Four techniques

  • Concrete examples — when a prose description of a transformation is interpreted inconsistently, 2-3 concrete input/output examples communicate the expected behavior far more reliably than more adjectives would.
  • Test-driven iteration — write the test suite (expected behavior, edge cases, performance requirements) before implementation, then iterate by sharing test failures back to guide progressive correction.
  • The interview pattern — have Claude ask clarifying questions first, surfacing considerations (cache invalidation strategy, failure modes) the developer hadn't yet thought through, before any implementation begins.
  • Batching related fixes — when multiple issues interact, describe them together in one detailed message; when they're independent, fix them sequentially instead.
Common miss Treating "the description was ambiguous" as a signal to write a longer, more detailed paragraph — rather than switching to concrete input/output examples, which resolve ambiguity more directly than prose ever can.

Check your understanding

Scenario
You've asked Claude to "handle null values sensibly" in a data migration script, but each run interprets "sensibly" differently — sometimes skipping the row, sometimes defaulting to zero, sometimes throwing. What's the most effective next step?
AProvide 2-3 concrete input/output examples showing exactly what should happen for specific null cases.
BRewrite the instruction with more detailed prose explaining what "sensibly" is intended to mean.
CAccept the first run's behavior as the standard and document it after the fact for future reference.
DSplit the null-handling logic into five separate prompts, one for each field that might contain nulls.
Correct This is the named fix for exactly this symptom: when prose produces inconsistent interpretation, concrete input/output examples resolve the ambiguity directly, in a way more prose reliably fails to.
Not quite More prose is the instinct the guide specifically calls out as ineffective here — it was already prose that produced the inconsistency. Accepting whatever the first run did skips fixing the actual ambiguity. Splitting into five separate prompts adds overhead without addressing that the core instruction itself is underspecified.
