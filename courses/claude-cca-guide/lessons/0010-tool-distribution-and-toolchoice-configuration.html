CCA-F · Domain 2 · Task Statement 2.3

Tool Distribution & tool_choice Configuration

More tools per agent doesn't mean more capable — past a point, it means less reliable.

Fewer, better-scoped tools

Giving an agent access to too many tools — the guide's example is 18 instead of 4-5 — degrades selection reliability simply by increasing decision complexity. Worse, agents given tools outside their actual specialization tend to misuse them: a synthesis agent with search access will sometimes go search instead of synthesizing what it's already been given.

The fix is scoped tool access: give each agent only what its role needs, with a small number of deliberately-chosen cross-role tools for genuinely high-frequency needs (a verify_fact tool on a synthesis agent, say), routing anything more complex back through the coordinator instead.

tool_choice as a precision instrument

  • "auto" — model may call a tool or just respond in text
  • "any" — model must call some tool, but picks which
  • Forced selection ({"type": "tool", "name": "..."}) — model must call this specific tool

Forced selection is useful for sequencing — forcing extract_metadata before enrichment tools run, then handling the rest in a follow-up turn. "any" guarantees a tool gets called at all, useful when a conversational text response would be the wrong outcome.

Check your understanding

Scenario
A synthesis subagent, whose job is to combine findings from other agents, has been given the full toolset of 16 tools used across the whole pipeline "just in case it needs something." It has started making occasional unnecessary web searches instead of synthesizing the findings it was already given. What's the most effective fix?
ARestrict the synthesis subagent's tool set to only the tools relevant to its actual role.
BAdd a system prompt instruction telling the synthesis agent to avoid using search tools.
CIncrease the synthesis agent's context window so it can better judge which tools are relevant.
DRename the search tools so their purpose is less obvious to the synthesis agent.
Correct This is the named failure mode directly — tools outside a subagent's specialization get misused. Scoping tool access to what the role actually needs fixes the root cause instead of patching around it.
Not quite A prompt instruction is a patch for a structural over-provisioning problem — it may reduce but won't eliminate the behavior, and doesn't scale to every other unnecessary tool. A bigger context window doesn't address decision complexity, which comes from tool count, not context size. Renaming tools to obscure their purpose damages usability without addressing why the agent has access to search at all.
