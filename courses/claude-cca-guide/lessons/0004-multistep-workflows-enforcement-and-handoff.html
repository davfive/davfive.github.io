CCA-F · Domain 1 · Task Statement 1.4

Multi-Step Workflows: Enforcement & Handoff

When a workflow step absolutely cannot be skipped, a well-worded instruction is not enough.

Two kinds of compliance

Programmatic enforcement (hooks, prerequisite gates) makes a step physically impossible to skip. Prompt-based guidance makes a step likely, not guaranteed. The exam's framing is blunt about this: when deterministic compliance is required — identity verification before a financial operation is the guide's own example — prompt instructions alone have a non-zero failure rate. That's not a criticism of prompting; it's a statement about what prompting can and can't guarantee.

Concretely A programmatic prerequisite blocks process_refund from executing until get_customer has returned a verified customer ID. The tool call literally cannot fire out of order — not "is unlikely to," cannot.

Handling multi-concern requests

When a single customer message bundles multiple distinct concerns, decompose it into separate items, investigate each in parallel using shared context, then synthesize one unified resolution — rather than answering the first concern you notice and dropping the rest.

Structured handoffs

When a workflow escalates mid-process to a human, that human has no access to the conversation transcript. A structured handoff summary — customer ID, root cause, amounts involved, recommended action — is what makes the handoff actually usable, versus a human starting from zero.

Check your understanding

Scenario
A refund agent occasionally processes refunds for unverified customers. The system prompt already says "always verify identity before refunds," but under complex multi-topic conversations it isn't always followed. What's the most effective fix?
AAdd a programmatic prerequisite that blocks the refund tool call until identity verification has completed.
BRewrite the system prompt to state the verification requirement in stronger, more emphatic language.
CAdd several few-shot examples showing the agent verifying identity before every refund request.
DReduce the number of tools available to the agent so refunds are simpler to process correctly.
Correct This is a case requiring deterministic compliance — financial operations are the guide's own example. However strongly worded, prompt instructions have a non-zero failure rate; a programmatic prerequisite gate makes the skip physically impossible rather than just unlikely.
Not quite Stronger wording and more few-shot examples both stay in the probabilistic-compliance world — they reduce but don't eliminate failures. Reducing available tools doesn't address ordering at all; fewer tools doesn't guarantee verification happens first. Deterministic requirements need deterministic enforcement.
