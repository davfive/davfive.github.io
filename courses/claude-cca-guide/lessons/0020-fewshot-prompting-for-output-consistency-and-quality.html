CCA-F · Domain 4 · Task Statement 4.2

Few-Shot Prompting for Output Consistency & Quality

Examples don't just show format — they teach judgment on the ambiguous cases that break rules-based prompting.

What few-shot actually buys you

When detailed instructions alone still produce inconsistent output, few-shot examples are the most effective fix. They do more than demonstrate formatting: showing 2-4 examples of ambiguous-case handling — which tool to pick for an ambiguous request, how to judge a borderline test-coverage gap — teaches the model to generalize the underlying judgment to novel cases it hasn't seen, rather than only matching the exact cases you listed.

Where the guide names concrete wins Demonstrating output format (location, issue, severity, suggested fix) for consistency · distinguishing acceptable patterns from genuine issues to cut false positives without losing generalization · showing correct extraction from varied document structures (inline citations vs. bibliographies) · reducing empty/null extraction on required fields by showing extraction from documents with varied formatting.

The examples that add the most value are the ones showing why one action was chosen over a plausible alternative — reasoning transfer, not just output-shape transfer.

Check your understanding

Scenario
An extraction pipeline pulling structured data from scientific papers frequently returns null for the "methodology" field — not because papers lack a methodology, but because it's sometimes described inline in the results section rather than under a dedicated heading. Detailed prose instructions haven't fixed this. What's the most effective next step?
AAdd few-shot examples showing correct methodology extraction from papers with varied document structures.
BAdd a fallback rule that defaults methodology to "not specified" whenever no dedicated heading exists.
CIncrease the model's output token limit so it has more room to search for methodology-related content.
DSplit methodology extraction into its own separate API call, run independently of the rest of the schema.
Correct This is a named example in the guide directly: few-shot examples demonstrating correct extraction from varied document structures fixes exactly this class of empty/null-field problem where prose instructions alone haven't.
Not quite Defaulting to "not specified" doesn't fix extraction — it just documents the failure instead of correcting it. A larger output limit doesn't address the actual problem, which is recognizing methodology content outside its expected location, not running out of room. Splitting into a separate call doesn't change what signal the model has to recognize inline methodology content in the first place.
