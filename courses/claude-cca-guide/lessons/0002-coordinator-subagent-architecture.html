CCA-F · Domain 1 · Task Statement 1.2

Coordinator-Subagent Hub-and-Spoke

The exam's favorite failure mode here isn't a bug in any one subagent — it's a decomposition decision the coordinator made before any subagent ran.

The pattern

Hub-and-spoke: a coordinator agent manages all inter-subagent communication, error handling, and information routing. Subagents never talk to each other directly — everything flows through the hub. This buys you three things: observability (one place to see everything), consistent error handling (one place to catch and react), and controlled information flow (no subagent gets more than it needs).

The detail that trips people up Subagents operate with isolated context. Spawning a subagent does not hand it the coordinator's conversation history automatically. If a subagent needs prior findings, tool results, or context from earlier in the session, the coordinator has to put that content directly into the subagent's prompt. This is the single most common source of "the subagent gave a generic/wrong answer" bugs.

The coordinator's actual job

Three responsibilities, in the exam's framing:

  • Task decomposition — breaking the overall goal into subtasks and deciding which subagents to invoke, dynamically, based on query complexity (not always routing through a fixed full pipeline).
  • Delegation — partitioning scope across subagents to minimize duplicated work (distinct subtopics or source types per agent, not overlapping ones).
  • Result aggregation — combining subagent outputs, and running iterative refinement: evaluating the synthesis for gaps, re-delegating to search/analysis subagents with targeted follow-up queries, and re-invoking synthesis until coverage is actually sufficient.

The named risk: overly narrow decomposition

This is worth sitting with, because it's the guide's signature trap for this task statement. The failure looks like this: every subagent completes its assigned work correctly — searches run fine, documents get analyzed correctly, synthesis is coherent — but the final output has a coverage gap. When you trace it back, the cause is never a broken subagent. It's that the coordinator's decomposition covered only part of the real topic space, and nothing was ever assigned to cover the rest.

Where people misdiagnose this The instinct is to blame the agent whose output looks thin — "the web search agent needs better queries" or "the synthesis agent is filtering things out." Both agents did their assigned jobs. The bug is one level up, in what they were assigned.

Check your understanding

Scenario
You spawn a synthesis subagent with the prompt "Combine findings from the other agents." Its output is generic and never references any of the actual research the other agents produced. What's the most likely cause?
ASubagents don't automatically inherit the coordinator's history, so findings must be included directly.
BThe synthesis subagent needs a larger context window to combine findings from multiple sources.
CThe coordinator should be removed and replaced by one agent with access to every tool.
DThe synthesis subagent's system prompt should be rewritten to sound more specific overall.
Correct Subagents have isolated context — spawning one doesn't hand it the coordinator's conversation history. With no actual findings in its prompt, the subagent has nothing concrete to synthesize and produces something generic by default.
Not quite B assumes a capacity problem, but the subagent has zero findings in context — no window size fixes that. C throws away the observability, error-handling, and routing control the hub-and-spoke pattern exists to provide, and still doesn't put the findings anywhere. D polishes wording without changing what information the subagent actually receives. Fix: pass the real findings into the prompt directly.
Scenario
A coordinator researching "emerging risks in global supply chains" decomposes it into three subagents: shipping route disruptions, port capacity constraints, and container shortages. The report is well-written but says nothing about cybersecurity, labor disputes, or raw material scarcity — all commonly cited supply-chain risks. What's the most likely root cause?
AThe coordinator's decomposition was too narrow, covering one risk category and omitting the others entirely.
BThe subagents' search queries were not comprehensive enough and should cover more sources.
CThe synthesis agent filtered out findings about cybersecurity, labor, and materials as irrelevant.
DThe report needs a longer context window so every risk category fits in a single pass.
Correct Same failure pattern the Exam Guide covers directly (see its own Sample Question on this exact topic — worth re-reading now). All three subagents were logistics/shipping-specific; cyber, labor, and materials risk were never assigned to anyone. No downstream fix recovers scope that was never delegated.
Not quite B and C both blame agents that executed their assigned scope correctly — there's nothing to search or synthesize for categories nobody was pointed at. D misreads this as a capacity problem; it's a scope problem. This is exactly why the guide treats "narrow decomposition" as its own architectural risk, distinct from any individual subagent's execution quality.
