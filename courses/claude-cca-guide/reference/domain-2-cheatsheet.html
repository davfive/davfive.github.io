Tool Design & MCP Integration

Print-friendly compression of all 5 Task Statements in this domain.

2.1 — Effective tool interfaces

  • Tool descriptions are the model's primary selection signal — include input formats, examples, and explicit boundaries vs. similar tools.
  • Fixes beyond wording: rename/re-describe, or split an overly generic tool into purpose-specific ones.

2.2 — Structured error responses

  • Four categories: transient, validation, business, permission. Uniform "failed" text collapses all of them.
  • Return errorCategory, isRetryable, and a human-readable description.
  • Access failure (timeout) ≠ valid empty result — don't conflate them.

2.3 — Tool distribution & tool_choice

  • Fewer, role-scoped tools beat broad access — over-provisioned agents misuse tools outside their specialty.
  • tool_choice: "auto" (may skip) · "any" (must call, picks which) · forced (must call this one).

2.4 — MCP servers in Claude Code

  • Project-scoped .mcp.json (shared, version-controlled) vs. user-scoped ~/.claude.json (personal/experimental).
  • Prefer existing community servers over custom builds for standard integrations.
  • MCP resources expose catalogs directly, cutting exploratory tool calls.

2.5 — Built-in tools

GrepContent search inside files
GlobFile path/name pattern matching
Read / WriteFull file operations

Wrapper-tracing patternFind all exported/re-exported names first, then Grep each one — a single direct-name search misses wrapped usages.

Glossary (Domain 2)

isError: MCP's tool-failure flag — needs structured category info alongside it to be useful.
tool_choice forced selection: {"type": "tool", "name": "..."}, guarantees a specific tool runs.
Scoped tool access: giving each agent only the tools its role actually needs.
