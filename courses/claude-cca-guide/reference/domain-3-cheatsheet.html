Claude Code Configuration & Workflows

Print-friendly compression of all 6 Task Statements in this domain.

3.1 — CLAUDE.md hierarchy

  • User-level (~/.claude/CLAUDE.md, personal, not shared) · project-level (shared via VCS) · directory-level (package/module-specific).
  • @import for modular standards; .claude/rules/ for topic-split files; /memory to diagnose what's actually loaded.

3.2 — Slash commands & skills

  • .claude/commands/ (project, shared) vs. ~/.claude/commands/ (personal).
  • Skill frontmatter: context: fork (isolate verbose output) · allowed-tools (restrict) · argument-hint (prompt for args).

3.3 — Path-specific rules

  • .claude/rules/ + YAML paths glob = loads only for matching files, regardless of directory.
  • Use for conventions defined by file type; use directory CLAUDE.md for conventions defined by location.

3.4 — Plan mode vs. direct execution

  • Plan mode: architectural decisions, multiple approaches, multi-file changes. Direct execution: simple, well-scoped changes.
  • Explore subagent isolates verbose discovery output to protect main context.

3.5 — Iterative refinement

  • Concrete input/output examples beat more prose for ambiguous transformations.
  • Test-driven iteration; the interview pattern (Claude asks first); batch interacting issues, sequence independent ones.

3.6 — CI/CD integration

  • -p/--print for non-interactive mode; --output-format json + --json-schema for structured findings.
  • Self-review is structurally weaker than independent review (shared reasoning context).
  • Include prior findings in context on re-runs to avoid duplicate comments.

Glossary (Domain 3)

context: fork: skill frontmatter option running the skill in an isolated sub-agent context.
Explore subagent: isolates verbose codebase discovery, returns a summary.
Session isolation (CI): the reason a generating session reviews its own code less effectively than an independent instance.
