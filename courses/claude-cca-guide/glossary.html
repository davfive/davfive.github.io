CCA-F Glossary

Compiled from all five domains. Terms are grounded in the official Exam Guide's Knowledge/Skills bullets, not paraphrased casually.

Domain 1 — Agentic Architecture & Orchestration

  • Hub-and-spoke: architecture where a coordinator routes all inter-agent communication; no agent talks directly to another.
  • Isolated context: a subagent's default state — no memory of the coordinator's prior conversation unless explicitly given it.
  • Narrow decomposition: a task breakdown that omits whole categories of a topic, not just under-executes one.
  • Deterministic enforcement: a hook or programmatic gate that makes skipping a step physically impossible, vs. prompt guidance which only makes it unlikely.
  • stop_reason: the API's structured signal (tool_use / end_turn) for why generation stopped — the only reliable agentic-loop control signal.

Domain 2 — Tool Design & MCP Integration

  • isError: MCP's tool-failure flag; needs structured category info (transient/validation/business/permission) alongside it to be useful.
  • tool_choice: "auto" (may skip), "any" (must call, picks which), or forced ({"type": "tool", "name": "..."}, must call this one).
  • Scoped tool access: giving each agent only the tools its role actually needs, to reduce misuse and selection complexity.
  • MCP resources: content catalogs a server exposes directly, cutting down exploratory tool calls.

Domain 3 — Claude Code Configuration & Workflows

  • CLAUDE.md hierarchy: user-level (personal, not shared), project-level (shared via VCS), directory-level (module-specific).
  • context: fork: skill frontmatter option that runs the skill in an isolated sub-agent context, keeping verbose output out of the main session.
  • Path-specific rules: .claude/rules/ files with YAML paths globs, loaded only when a matching file is being edited.
  • Explore subagent: isolates verbose codebase discovery, returning only a summary to the main conversation.
  • Session isolation (CI): the reason a generating session reviews its own code less effectively than an independent review instance.

Domain 4 — Prompt Engineering & Structured Output

  • Explicit criteria: concrete, checkable review/classification rules, as opposed to vague guidance like "be conservative."
  • Few-shot generalization: examples of ambiguous-case handling that teach transferable judgment, not just output format.
  • Semantic vs. syntax error: tool_use/JSON schemas eliminate syntax errors; they do not catch values that are individually well-formed but collectively wrong (e.g., totals that don't sum).
  • Message Batches API: 50% cost savings, up to 24-hour processing window, no latency SLA, no mid-request multi-turn tool calling.
  • Self-review limitation: a model is less likely to question decisions it just made in the same session, regardless of instruction or extended thinking.

Domain 5 — Context Management & Reliability

  • Lost in the middle: the effect where models reliably attend to the start/end of long inputs but may drop findings from the middle.
  • Case facts block: a persistent, non-summarized record of transactional facts (amounts, dates, IDs) carried in every prompt.
  • Access failure vs. valid empty result: a timeout needing a retry decision, vs. a successful query that legitimately found nothing — must be reported differently.
  • Coverage annotation: synthesis metadata distinguishing well-supported findings from areas with real evidentiary gaps.
  • Claim-source mapping: structured attribution (source, excerpt) that must be preserved, not dropped, through every synthesis stage.
