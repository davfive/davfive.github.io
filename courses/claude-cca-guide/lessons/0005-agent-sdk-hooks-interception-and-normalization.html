Agent SDK Hooks: Interception & Normalization

Hooks are where you put guarantees that can't live in a prompt.

Two hook use cases

Normalizing incoming results. A PostToolUse hook intercepts tool results before the model ever sees them — useful when different MCP tools return the same kind of data in different shapes (a Unix timestamp from one, ISO 8601 from another, a numeric status code from a third). Normalize at the boundary, and the model never has to reconcile the discrepancy itself.

Blocking outgoing calls. A hook can also intercept an outgoing tool call and block it outright when it violates a business rule — refunds above a threshold, for instance — redirecting to an alternative workflow like human escalation.

Same principle as Task 1.4 Hooks give deterministic guarantees. Prompt instructions give probabilistic compliance. Reach for a hook specifically when the business rule cannot be allowed to fail even occasionally.

Check your understanding

Scenario
Your agent pulls order data from three different MCP tools, each returning dates in a different format (Unix timestamp, ISO 8601, and "MM/DD/YYYY"). The agent frequently miscalculates date differences. What's the most effective fix?
AImplement a PostToolUse hook that normalizes all date formats before the results reach the model.
BAdd a system prompt instruction asking the model to carefully parse each date format correctly.
CAsk the model to always double-check its date math before presenting results to the user.
DRestrict the agent to only using the MCP tool with the date format that's easiest to parse.
Correct This is exactly the normalization use case for PostToolUse hooks: intercept tool results and transform them into one consistent format before the model has to reason about the discrepancy at all.
Not quite Asking for careful parsing and asking for double-checked math both push a data-quality problem onto the model's reasoning, which stays unreliable — the model can still misparse an ambiguous format. Restricting to one tool loses functionality just to dodge the problem instead of fixing it. Normalize at the boundary; don't push the burden onto the model.
