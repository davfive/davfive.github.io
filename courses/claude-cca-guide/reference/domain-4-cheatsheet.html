CCA-F · Reference · Domain 4 (20% of exam)

Prompt Engineering & Structured Output

Print-friendly compression of all 6 Task Statements in this domain.

4.1 — Explicit criteria

  • "Be conservative" isn't a criterion — it gives no concrete threshold. Behavioral criteria ("flag only when X contradicts Y") do.
  • High false-positive categories erode trust in every other category the same system reports.

4.2 — Few-shot prompting

  • Most effective fix when detailed prose still produces inconsistent output.
  • 2-4 examples of ambiguous-case handling teach generalizable judgment, not just format.

4.3 — Structured output via tool use

  • tool_use + JSON schema eliminates syntax errors, not semantic ones (sums, wrong fields).
  • Nullable/optional fields prevent fabrication when info is genuinely absent from the source.

4.4 — Validation, retry, feedback loops

  • Retry-with-error-feedback fixes semantic/format errors. It cannot fix information absent from the source.
  • detected_pattern fields enable systematic false-positive analysis over time.

4.5 — Batch processing

  • Message Batches API: 50% cost savings, up to 24h window, no latency SLA. No multi-turn tool calling mid-request.
  • Fits non-blocking workloads (overnight/weekly); wrong fit for pre-merge blocking checks.

4.6 — Multi-instance & multi-pass review

  • Self-review is weak because the session retains its own generation reasoning — not a matter of effort.
  • Split large reviews into per-file passes + a separate cross-file integration pass.

Glossary (Domain 4)

tool_choice "any": model must call some tool but picks which — useful when the document type is unknown ahead of time.
custom_id: correlates a batch request with its response.
Self-review limitation: a model is less likely to question decisions it just made in the same session.
