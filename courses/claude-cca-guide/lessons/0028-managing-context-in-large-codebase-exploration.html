CCA-F · Domain 5 · Task Statement 5.4

Managing Context in Large Codebase Exploration

Long exploration sessions degrade quietly — the fix is externalizing memory, not trying harder to remember.

How degradation shows up

In extended sessions, a model can start giving inconsistent answers and referencing "typical patterns" in generic terms rather than the specific classes it actually discovered earlier in the same session — a sign that earlier findings have effectively fallen out of usable context.

Externalizing memory

  • Scratchpad files — persist key findings across context boundaries so later questions can reference concrete earlier discoveries instead of the model's fading recollection of them.
  • Subagent delegation — spawn subagents for specific investigative questions ("find all test files," "trace refund flow dependencies") while the main agent stays focused on high-level coordination rather than drowning in exploration detail itself.
  • Phase summaries — summarize key findings from one exploration phase, and inject that summary into the next phase's initial context, before spawning subagents for it.
  • /compact — reduces context usage mid-session once it's filled with verbose discovery output.
Crash recovery, structurally Each agent exports its state to a known location as it works. On resume, the coordinator loads a manifest of that exported state and injects it back into agent prompts — recovery becomes a data-loading problem, not a re-exploration problem.

Check your understanding

Scenario
After several hours of codebase exploration in one long session, the agent starts referring to "the typical repository pattern" in generic terms, even though 40 minutes earlier it had identified three specific, differently-structured repository classes by name. What's the most effective fix going forward?
AHave the agent maintain a scratchpad file recording specific findings, and reference it in later questions.
BEnd the session and start a completely new one so the model isn't carrying any prior context at all.
CInstruct the model to try harder to remember the specific class names discussed earlier in the session.
DReduce the number of files the agent is allowed to explore so less total information needs to be tracked.
Correct This is the guide's stated fix for exactly this degradation pattern: externalizing key findings to a scratchpad file counteracts the fading of specific details in long sessions, since later steps can reference the concrete record rather than relying on in-context recall.
Not quite Starting over loses the three repository classes already found, requiring redundant re-discovery. "Try harder to remember" isn't a real lever — the problem is a structural context-degradation effect, not effort. Limiting file exploration reduces the value of the investigation itself rather than fixing how findings are retained.
