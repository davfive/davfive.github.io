CCA-F · Domain 3 · Task Statement 3.2

Custom Slash Commands & Skills Configuration

Skills carry real configuration surface: where they live, whether they fork, and what tools they can touch.

Commands: project vs. personal

Slash commands in .claude/commands/ are project-scoped and version-controlled — shared with the whole team. Commands in ~/.claude/commands/ are user-scoped and personal.

Skills frontmatter that actually matters

  • context: fork — runs the skill in an isolated sub-agent context, so its (often verbose) output doesn't pollute the main conversation. Ideal for codebase analysis or exploratory brainstorming that generates a lot of intermediate noise.
  • allowed-tools — restricts which tools the skill can invoke during execution (e.g., limiting to file-write only, to prevent a skill from taking destructive actions it doesn't need).
  • argument-hint — prompts the developer for required parameters if they invoke the skill without arguments.

Personal variants of a skill can live in ~/.claude/skills/ under a different name — customize your own workflow without changing what teammates get from the shared version.

Skills vs. CLAUDE.md Skills are for on-demand, task-specific workflows you invoke when needed. CLAUDE.md is for universal standards that should always be loaded, every session, without being asked for.

Check your understanding

Scenario
A skill performs a large, verbose codebase analysis, and its full intermediate output — file listings, partial findings, dead ends — has been cluttering the main conversation and eating context budget every time it runs. What frontmatter option addresses this directly?
Acontext: fork, so the skill's exploration runs in an isolated sub-agent and only its result returns.
Ballowed-tools, restricted to Read only, so the skill can no longer explore as much of the codebase.
Cargument-hint, so developers are prompted to describe what they want analyzed before running it.
DRewriting the skill as a project-scoped slash command instead of a skill in .claude/skills/.
Correct context: fork exists precisely for this: isolating verbose or exploratory output in a sub-agent context so it never pollutes the main session, while still returning a usable result.
Not quite allowed-tools controls which tools can run, not where output lands — restricting to Read would also cripple the analysis itself. argument-hint only affects how missing arguments are requested, not output volume. Converting to a slash command doesn't change the isolation problem; commands don't have the fork behavior skills do.
