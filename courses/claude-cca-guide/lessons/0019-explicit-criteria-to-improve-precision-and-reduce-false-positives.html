CCA-F · Domain 4 · Task Statement 4.1

Explicit Criteria to Improve Precision & Reduce False Positives

"Be conservative" is not a criterion. It's a hope.

Specific beats vague, every time

Compare "check that comments are accurate" against "flag comments only when claimed behavior contradicts actual code behavior." Both sound like similar instructions; only the second gives the model something concrete to check against. General guidance like "be conservative" or "only report high-confidence findings" doesn't actually improve precision — it just asks the model to guess at a threshold you never defined.

The trust cost of false positives False positives aren't evenly costly. A category with a high false-positive rate erodes trust in every other category the same system reports on — developers stop reading all the findings, not just the noisy ones.

What actually works

Write criteria that explicitly define what to report (bugs, security issues) versus what to skip (minor style, local team patterns) — rather than relying on the model's own confidence estimate to filter. For severity classification specifically, give concrete code examples at each severity level, not just adjectives ("critical," "minor") on their own.

Check your understanding

Scenario
A code-review agent flags too many comment/behavior mismatches that turn out to be non-issues on inspection. The current instruction says "only report high-confidence findings" and "be conservative." Developers have started ignoring the review entirely. What's the most effective fix?
AReplace the vague guidance with an explicit criterion: flag only when claimed behavior contradicts actual code behavior.
BStrengthen the wording to "be extremely conservative and only report near-certain findings."
CRemove comment-accuracy checking from the review entirely since it can't be made reliable.
DAsk the model to self-report a numeric confidence score and only surface findings above 90%.
Correct This is the exact contrast the guide draws: a concrete behavioral criterion (claimed vs. actual behavior) gives the model something to check, where "be conservative" only asks it to guess at an undefined threshold.
Not quite Intensifying the same vague language ("extremely conservative") doesn't give the model a new signal to act on — it's still asking for calibration without providing criteria. Removing the check entirely throws away a category that could be fixed with better criteria instead. Self-reported confidence scores are exactly the kind of proxy the guide flags as unreliable for filtering precision.
